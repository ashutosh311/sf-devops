Purpose

The Slalom AI SDLC tool embeds Slalom UK&I's Salesforce delivery methodology directly into developer workflows. It provides a suite of AI agents — one per delivery phase — that guide teams from initial discovery through to production release, enforcing coding standards and managing JIRA transitions without context-switching.

The tool runs as a GitHub Copilot chat participant inside VS Code. You invoke it by tagging @otto in the Copilot Chat panel and running a phase command.

Agents are phase-gated: each has a defined scope and will not cross into adjacent phases, ensuring clean handovers and traceable artefacts committed to source control.

1
Install VS Code

If you do not already have VS Code installed, download and install it first.

1
Download VS Code Visit code.visualstudio.com and download the installer for your operating system (macOS, Windows, or Linux).
2
Run the installer Follow the prompts. On macOS, drag VS Code to Applications. On Windows, accept the defaults — ticking "Add to PATH" is recommended.
3
Open VS Code and verify Launch VS Code from your Applications folder or Start menu. The version is shown at Help → About.
ℹ️ VS Code 1.90 or later is required for the Slalom Otto extension and GitHub Copilot Chat.
2
Install the Salesforce Extension Pack

The Salesforce Extension Pack adds Apex syntax highlighting, code completion, org management, and deployment tooling to VS Code.

1
Open the Extensions panel Press Cmd+Shift+X (macOS) or Ctrl+Shift+X (Windows/Linux), or click the Extensions icon in the left activity bar.
2
Search for "Salesforce Extension Pack" Type the name in the search box. Look for the result published by Salesforce (it has the Salesforce cloud logo).
3
Click Install and reload VS Code will install a bundle of extensions including Apex language support, LWC tools, and Salesforce CLI integration. Reload when prompted.
3
Install Salesforce CLI

The Salesforce CLI (sf) is a command-line tool used to authenticate to orgs, deploy metadata, and run tests. The SDLC tool uses it to interact with your sandbox.

macOS (Homebrew):

brew install sf

Windows / Linux: Download the installer from developer.salesforce.com/tools/salesforcecli and follow the setup wizard.

Verify the install by opening a terminal and running:

sf --version
Authenticate your sandbox

Run the following to log in to your development sandbox and give it an alias. The alias is what the SDLC tool uses to reference the org — pick something short and memorable.

sf org login web --alias dev --instance-url https://test.salesforce.com

This opens a browser login. After authenticating, the alias dev refers to that org in all CLI commands. To list your connected orgs at any time:

sf org list
💡 Make a note of the alias you choose — you will be asked to enter it during the /init setup in Step 7.
4
Set Up GitHub Copilot

The Slalom Otto extension runs inside GitHub Copilot Chat. You need an active Copilot subscription and the extensions installed in VS Code.

1
Install GitHub Copilot and Copilot Chat Open the Extensions panel (Cmd/Ctrl+Shift+X), search for "GitHub Copilot", and install both GitHub Copilot and GitHub Copilot Chat (published by GitHub).
2
Sign in to GitHub Click the Copilot icon in the activity bar (or the Accounts icon at the bottom-left) and sign in with your GitHub account.
3
Confirm your subscription Your account needs an active Copilot licence. If your organisation provides licences, confirm your account has been assigned one via github.com/settings/copilot.
4
Open Copilot Chat Press Ctrl+Alt+I (macOS: Cmd+Alt+I) or click the chat icon in the activity bar. The chat panel should open on the right-hand side.
5
Set Up the Atlassian MCP Server

The SDLC tool connects to JIRA to read story details and update ticket statuses. This is handled by an MCP (Model Context Protocol) server that manages your Atlassian OAuth session — think of it as a secure bridge between Copilot and JIRA.

After running /init in Step 7, a file .vscode/mcp.json will be created in your project repository. VS Code reads this file automatically and makes the Atlassian server available in Copilot Chat.

1
Open Copilot Chat Open the chat panel (Cmd/Ctrl+Alt+I).
2
Click the Tools icon At the bottom of the chat input box, click the plug icon labelled Tools. This shows all available MCP servers.
3
Connect Atlassian Find Atlassian in the list and click Connect. A browser window will open asking you to authorise access to your Atlassian account — log in and approve.
⚠️ The Atlassian server only appears in the Tools list after /init has been run and .vscode/mcp.json exists. Complete Step 7 first, then return here to connect.
6
Install the Slalom Otto Extension

Obtain the slalom-sdlc-*.vsix file from your delivery lead or technical architect, then install it manually in VS Code.

1
Open the Extensions panel Press Cmd/Ctrl+Shift+X.
2
Install from VSIX Click the ··· menu in the top-right corner of the Extensions panel, then select Install from VSIX… and choose the file.
3
Reload VS Code Reload when prompted to activate the extension.
4
Verify Open Copilot Chat and type @otto /about. You should see a help message listing all available commands.
🔄 Instructions stay up to date automatically. The methodology that drives each agent is compiled into the extension and refreshed daily in the background from the Slalom/salesforce-devops GitHub repository, using your existing VS Code GitHub login — no reinstall needed. If you have no GitHub access (e.g. a client team), the instructions bundled into your VSIX are used as-is and work fully offline. See Keeping Instructions Up to Date.

Running the Agents

Invoke agents in the Copilot Chat panel by tagging @otto followed by the phase command. Run them in order as a story progresses through the board.

🔭 @otto /discover

Maps requirements, drafts epics, stories, and sprint allocation plan.

Run once per engagement
✏️ @otto /refine PROJ-42

Adds Gherkin acceptance criteria, INVEST validation, and effort estimate.

Sprint −1
🏗️ @otto /design PROJ-42

Org discovery, solution design doc, and JIRA sub-tasks.

Sprint −1
⚙️ @otto /build PROJ-42

Apex / LWC scaffolding, metadata, deployment to sandbox.

Sprint
🧪 @otto /test PROJ-42

Apex test classes, Jest tests, and coverage validation.

Sprint
🚀 @otto /release

Deployment runbook, handover checklist, and JIRA transitions.

Transition

Replace PROJ-42 with the JIRA key of the story you are working on.

Keeping Instructions Up to Date

Slalom's delivery methodology improves over time. The instructions that drive each agent are never written into your project — they live inside the extension and refresh automatically, so you stay on the latest best practice without reinstalling.

What How it works
Automatic refresh On startup the extension silently checks (at most once every 24 hours) for a newer instruction release on Slalom/salesforce-devops. If found, it downloads, verifies checksums, and activates it atomically.
Offline fallback If there is no internet, GitHub access, or sign-in, the instructions compiled into your installed VSIX are used. Your work is never interrupted.
Authentication Background refresh reuses your existing VS Code GitHub login silently. The first time you run Slalom Otto: Sync Instructions manually, VS Code may prompt you once to sign in / grant repository access.

Two commands are available from the Command Palette (Cmd/Ctrl+Shift+P):

Command What it does
Slalom Otto: Instruction Status Shows the active instruction version, last sync time, and any errors.
Slalom Otto: Sync Instructions Forces an immediate refresh without waiting for the 24-hour window.
📦 For client / non-Slalom teams: a VSIX works fully offline. The instructions bundled into the build you were given are available immediately — no GitHub access or internet connection is required, and the sync simply does nothing.
Agent Boundaries

Each agent has a defined remit and will not take actions outside its phase. This enforces clean handovers and keeps artefacts traceable.

Agent In scope Out of scope
/refine Acceptance criteria, INVEST validation, effort estimate Technical decisions, code
/design Org discovery, solution design, JIRA sub-tasks Implementation code, deployments
/build Code scaffolding, deployment to sandbox Refinement, design changes
/test Test generation, coverage validation Implementation changes
/release Deployment runbook, JIRA transitions Code generation, testing
Coding Standards Summary

The standards scaffolded into devops/standards/ are enforced by the build and test agents. Full detail is in the standards files after /init.

⚡
Triggers One per SObject. All events declared in a single trigger. One handler call per trigger.
📋
Logging Logger.info/warn/error() only. No System.debug in any submitted code.
🔍
SOQL In Selector classes only. Never inline in triggers, handlers, or service layers.
💾
DML Via UnitOfWork only. Never direct DML in business logic.
🚩
Feature flags FeatureToggle__mdt custom metadata. No hardcoded conditionals.
🧪
Test classes Non-DML pattern, StubBuilder mocks, bulk tested at 200 records, ≥85% coverage.
💬
Commits Conventional Commits: type(scope): summary — 72 chars max.
🌿
Branches type/JIRA-KEY-description — e.g. feat/ACME-42-opportunity-trigger

Troubleshooting
Symptom What to check
@otto not appearing in chat Reload VS Code. Confirm the extension shows as Enabled in the Extensions panel.
/init fails to fetch standards Confirm you have access to the Slalom/salesforce-devops GitHub repository. Check with your delivery lead if unsure.
Instructions out of date / sync failing Run Slalom Otto: Instruction Status from the Command Palette. If sign-in is needed, run Slalom Otto: Sync Instructions and approve the GitHub prompt.
JIRA transitions not working Re-connect the Atlassian MCP server via the Tools icon in the Copilot Chat panel.
Atlassian server not in Tools list Confirm .vscode/mcp.json exists in your project root, then reload VS Code.
Sandbox deploy fails Run sf org list and confirm the alias in .sdlc/config.json matches exactly.
Copilot Chat not responding Confirm your GitHub Copilot subscription is active and you are signed in (Accounts icon, bottom-left of VS Code).
